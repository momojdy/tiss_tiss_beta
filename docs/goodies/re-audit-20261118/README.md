## Implemented behavior

**Customer:** address edits invalidate stale coordinates and preserve actual street/postal fields; address/preferences/notifications/payment/support loads and writes have account guards, duplicate locks, safe errors and retry states. Notifications paginate and open the requested product. Missing stores do not crash historical orders or carts. Checkout and 3DS use immutable submitted snapshots, keep later cart edits and recover per-account idempotency keys. Invalid financial responses stay unavailable instead of becoming `$0`. Support confirms an actual persisted receipt and reaches the real admin queue. [Detailed customer receipt](customer.json).

**Vendor:** product saves preserve committed photos if later cleanup fails; duplicate actions lock synchronously. Store activation, builder loads/cache failures, private proof viewing, paging and signout have accurate states. Generic builders and the shared Wallet route are reachable. Missing opening-hour days normalize to closed. Owner/admin write permissions remain server-authoritative; read-only staff retain permitted reads. The dedicated Goodies vendor catalog has 411 editable labels in `en`, `fr`, `es`, `zh-Hans`, canonical option IDs remain stable, and equal translated captions cannot merge distinct choices. [Vendor](vendor.json) and [localization](vendor-localization.json) receipts.

**Admin:** every advertised Goodies hub module maps to a real registered destination, including Support; prototype workspace fallthrough is avoided. Operations versus finance privileges are separated in UI and backend. Invitation acceptance is database-owned rather than editable user metadata. CMS saves/publication/uploads and operational/financial decisions have duplicate locks, session guards, receipt checks and honest partial-failure states. Ingredient requests page beyond 200 and apply waiting filters before pagination. Builder preview selection includes the merchant while preserving stored IDs. [Admin implementation evidence](https://github.com/momojdy/tiss-admin/blob/14e3d589552ac09eb5bcfcbf7bbef85569ddd5a5/docs/goodies/re-audit-20261118/admin.json).

**Courier and maps:** real stored coordinates and actual routing geometry are retained; invalid coordinate types are rejected, stale samples are filtered, and GPS messages follow locale changes. Current account/assignment guards protect late callbacks. Couriers receive actual pickup name/address and a complete valid coordinate pair, with native-map links and correct viewport fallback. Server mutations use order-before-assignment lock ordering, recheck roster/order/assignment/status, prevent removed couriers completing delivery and require resolving physical pickup before removal. No synthetic courier movement or invented road route was introduced. Actual phone GPS, routing-provider configuration and background behavior are still unverified. [Courier](courier.json), [backend](backend.json) receipts.

**Financial and Shared Bill:** actual SQL tests cover server prices/builders, a 5,000 HTG total-sales allowance, 24-hour dispute hold, weekly settlement, instant Wantiss Wallet payout, two-day digital-wallet scheduling and 7–14 business-day bank scheduling. Concurrent Shared Bill creator 60% reservations and remaining 40% contributions create one original-customer paid order, one stock reservation and no duplicate debit. Cancellation, expiry, rejection and interrupted/failed finalization refund original payers idempotently. Recovered/lost responses, account/group changes and simultaneous taps retain accurate client state. External payout delivery and positive card-provider flows are not established by schedule/unit tests. New settlement/funding/upload gates remain off. [Group](group.json), [backend](backend.json), [24-migration plan](production-change-plan.json).

**Restrictions and CMS:** a reproduced defect allowed restricted shops to republish and accept new orders. The forward migration now checks business and owner/admin restrictions in catalog visibility, publication, canonical checkout, quote eligibility and Shared Bill finalization, with database locking against simultaneous restriction decisions. Existing fulfillment/cancellations/refunds remain operable; lifting restrictions restores eligible sales. The final CMS guard covers all newly added critical labels and denies unreviewed critical draft publishing. [Before/after logs](final-logs), [backend receipt](backend.json).
