Use approved synthetic accounts and a provider sandbox. Do not test with real charges or destructive customer records. This plan is not a claim that these scenarios were executed.

1. **Catalog:** vendor saves a real product/gallery and storefront → pending moderation → admin rejects with a reason → vendor sees the same reason → customer cannot purchase it, including after an availability toggle → content edit returns it to pending → admin approves → customer sees the real product. Another vendor/customer/courier must be denied private writes and reads.
2. **Shopping:** home/category/search/filter/store/product/gallery/builders → configure valid and invalid selections → quantity/note/cart edit → remove an unavailable historical store/product → retry catalog failure and recover offline cache. Verify displayed options and authoritative checkout totals agree. Never substitute sample inventory/reviews.
3. **Checkout:** saved address/contact, pickup/delivery/schedule, server quote, discounts/fees/tip, cash/wallet/card where enabled. Test stale quote, changed prices/availability, insufficient funds, lost responses, double taps and the same idempotency key. One charge/order only; invalid prices/fees/status updates must fail server-side.
4. **Group orders:** real host/member invitation, access revocation, expiry, shared cart update/removal, quote review and host-only wallet checkout. Paid lines clear once; late responses cannot cross accounts; vendor/admin receive the same resulting order. New Shared Bill funding remains excluded until separate multi-payer escrow/refund/exactly-once acceptance passes.
5. **Fulfillment:** customer checkout → vendor accept/prepare/ready → courier assignment/handoff → real GPS and road route → delivery → customer confirmation → 24-hour hold → weekly settlement. Verify customer, vendor and admin statuses, correct notification recipients, one notification per event and correct navigation after app reopen.
6. **Delivery failures:** location denial, background/restart, offline interruption, stale GPS beyond the freshness window, missing route, courier reassignment and removed store coordinates. No fabricated position/road route. Verify private proof upload/read rules for assigned courier, owner customer, own vendor, authorized admin and denied other identities. Test on physical Android and iOS.
7. **Cancellation/refunds:** customer/vendor/admin cancellation rules, webhook replay/out-of-order events, full/partial refunds, worker retries/dead letters, dispute resolution and reconciliation. Only sandbox provider evidence can establish the provider boundary; synthetic unit decisions do not replace it.
8. **Settlement:** gross cash sales cannot exceed 5,000 HTG exposure; the cap is not 5,000 HTG of fees. Confirm commission collection, refund adjustments, inactive/stale FX rejection, 24-hour hold, weekly eligibility, idempotent Wantiss Wallet payout and audited external/manual receipts. Verify two-day digital and 7–14 bank business-day windows against reviewed country calendars. Do not activate historical liabilities without opening reconciliation.
9. **CMS:** for each entry in the screen/control register, select the actual element → change draft text/asset/locale → preview → publish as an authorized admin → reload an installed customer. Verify draft isolation, restricted staff denials, English fallback for unfinished Creole, reviewed translation placeholders, notification copy and unchanged financial controls. Approved FAQ/policy/support content is required.
10. **Build/recovery:** clean install, checks and CI; signed Android/iOS builds; Maps provider restrictions, push foreground/background/reopen, production backup/restore rehearsal and a documented forward recovery. A JavaScript export alone is not signed-device acceptance.
